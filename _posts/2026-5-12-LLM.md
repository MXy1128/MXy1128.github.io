# 一、开发环境管理 —— UV

## 1. 什么是 UV

今天学习并配置了 `uv`，它是一个用于 Python 环境与依赖管理的工具，可以理解为：

> 一个比 pip + venv 更快、更现代化的 Python 包管理工具。

其核心作用包括：

- 创建虚拟环境
- 安装依赖
- 管理 Python 版本
- 加速依赖下载
- 替代部分 pip、virtualenv、poetry 的功能

---

## 2. 为什么要使用 UV

传统 Python 环境存在以下问题：

- 不同项目依赖冲突
- 环境难以复现
- pip 安装速度慢
- requirements.txt 管理混乱

而 `uv` 的优势：

| 功能 | 传统方式 | uv |
|---|---|---|
| 创建环境 | venv | uv venv |
| 安装依赖 | pip install | uv pip install |
| 速度 | 较慢 | 极快 |
| 环境隔离 | 支持 | 支持 |
| 依赖管理 | 一般 | 更现代 |

---

## 3. UV 的常用命令

```bash
# 创建虚拟环境
uv venv

# 激活环境（Windows）
.venv\Scripts\activate

# 安装依赖
uv pip install openai

# 查看已安装包
uv pip list
```

# 二、大模型的调用方式

## 1. 调用大模型需要的核心内容

今天学习了调用大模型的基本结构，通常需要三个核心参数：

| 参数 | 作用 |
|---|---|
| API Key | 身份认证 |
| Base URL | 请求地址 |
| Model Name | 指定调用模型 |

---

## 2. 大模型调用的本质

本质上：

> 向远程 AI 服务器发送 HTTP 请求，然后获得模型返回结果。

流程如下：

```text
用户输入
   ↓
代码发送请求
   ↓
大模型服务器推理
   ↓
返回生成结果
```

---

## 3. 一个典型的大模型调用流程

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的API_KEY",
    base_url="模型接口URL"
)

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "user", "content": "你好"}
    ]
)

print(response.choices[0].message.content)
```

# 三、LangChain 框架

## 1. 什么是 LangChain

今天了解了：

> LangChain 是一个用于开发 LLM（大语言模型）应用和智能体的框架。

它的作用是：

- 封装大模型调用
- 管理 Prompt
- 管理记忆（Memory）
- 调用工具（Tools）
- 构建 Agent
- 构建 AI 工作流

---

## 2. 为什么需要 LangChain

如果不用框架：

- 所有逻辑都要自己写
- 工具调用难管理
- Prompt 难维护
- 多步骤流程复杂

LangChain 可以帮助：

```text
模型 + 工具 + 记忆 + 推理流程
                ↓
          统一管理
```

---

## 3. LangChain 的核心模块

| 模块 | 作用 |
|---|---|
| LLM | 大模型 |
| PromptTemplate | 提示词模板 |
| Memory | 上下文记忆 |
| Tools | 工具调用 |
| Chains | 工作流 |
| Agent | 智能体 |

# 四、智能体（Agent）调用流程

## 1. 什么是 Agent

Agent（智能体）的本质：

> 能够自主思考、决定是否调用工具，并完成复杂任务的 AI 系统。

普通聊天模型：

```text
输入 → 输出
```

Agent：

```text
输入
 ↓
思考
 ↓
是否需要工具
 ↓
调用工具
 ↓
获得结果
 ↓
继续思考
 ↓
输出答案
```

---

## 2. Agent 的核心能力

### （1）推理能力

模型会先分析问题：

- 是否需要搜索
- 是否需要计算
- 是否需要数据库
- 是否需要代码执行

---

### （2）工具调用能力

Agent 最大的特点：

> 不仅会“说”，还会“做”。

例如：

- 调用搜索工具
- 调用天气 API
- 执行 Python 代码
- 查询数据库
- 调用浏览器

---

### （3）多步任务能力

复杂任务会拆解：

```text
用户需求
 ↓
任务拆分
 ↓
逐步执行
 ↓
汇总结果
```

这也是智能体相比普通聊天机器人的核心升级。

---

# 五、工具（Tools）的使用

## 1. 什么是 Tool

Tool 本质上是：

> 提供给大模型调用的外部函数。

例如：

```python
def search_weather(city):
    return "25度"
```

模型可以决定：

```text
我需要天气信息
→ 调用工具
→ 获取结果
→ 返回给用户
```

---

## 2. Tool 的意义

因为：

> 大模型本身不能直接访问现实世界。

所以需要：

- 搜索工具
- 数据库工具
- 文件工具
- API 工具
- 代码执行工具

来增强能力。

---

# 六、流式输出与 Invoke 输出

## 1. Invoke 输出

Invoke：

```python
llm.invoke("你好")
```

特点：

- 一次性返回完整结果
- 简单直接
- 类似普通函数调用

适合：

- 简单问答
- 后端接口

---

## 2. 流式输出（Streaming）

流式输出：

```python
for chunk in llm.stream("你好"):
    print(chunk)
```

特点：

- 边生成边输出
- 类似 ChatGPT 打字效果
- 用户体验更好

---

## 3. 两者区别

| 类型 | 特点 |
|---|---|
| Invoke | 一次性返回 |
| Stream | 实时逐步返回 |

---

# 七、Prompt（提示词）

## 1. Prompt 的作用

Prompt 是：

> 给大模型的“指令”。

模型的行为高度依赖 Prompt。

同一个模型：

- Prompt 不同
- 输出效果差异巨大

---

## 2. Prompt 的核心作用

包括：

- 约束模型行为
- 指定输出格式
- 提供背景信息
- 设定身份角色
- 控制回答风格

---

## 3. Prompt 工程的本质

Prompt Engineering（提示词工程）本质是：

> 用更好的指令，引导模型更稳定地产生目标结果。

---

# 八、如何设置 Prompt

## 1. 一个优秀 Prompt 的结构

通常包括：

```text
角色
任务
约束
输出格式
示例
```

---

## 2. 示例

```text
你是一名资深 Python 工程师，
请帮我分析以下代码问题，
要求：
1. 给出错误原因
2. 给出修改方案
3. 输出完整代码
```

---

## 3. Prompt 优化技巧

### （1）明确任务

不要：

```text
帮我看看
```

而是：

```text
分析报错原因并修复
```

---

### （2）指定格式

例如：

```text
请使用 Markdown 表格输出
```

---

### （3）给模型身份

例如：

```text
你是一名 AI 架构师
```

这样模型会更稳定。

---

# 九、不同角色（Role）的消息

大模型聊天接口通常有三种角色：

| Role | 作用 |
|---|---|
| system | 系统设定 |
| user | 用户输入 |
| assistant | 模型回复 |

---

## 1. System Message

作用：

> 定义模型长期行为。

例如：

```python
{
  "role": "system",
  "content": "你是一名专业AI工程师"
}
```

优先级最高。

---

## 2. User Message

用户真实问题：

```python
{
  "role": "user",
  "content": "帮我写Python代码"
}
```

---

## 3. Assistant Message

模型历史回答：

用于保持上下文记忆。

# 十、Agent 原理

## 1. Agent 的核心思想

Agent = 大模型 + 工具 + 推理循环

核心流程：

```text
用户问题
 ↓
LLM 分析
 ↓
决定是否调用工具
 ↓
执行工具
 ↓
获取结果
 ↓
再次推理
 ↓
最终回答
```

---

## 2. ReAct 思想

很多 Agent 使用：

> ReAct（Reason + Act）

即：

```text
思考（Reason）
↓
行动（Act）
↓
观察结果（Observation）
↓
继续思考
```

这是目前主流 Agent 的核心机制。

---

## 3. Agent 与普通聊天机器人的区别

| 普通 LLM | Agent |
|---|---|
| 只能回答 | 可以执行任务 |
| 无工具 | 可调用工具 |
| 单轮生成 | 多步推理 |
| 被动响应 | 主动规划 |
